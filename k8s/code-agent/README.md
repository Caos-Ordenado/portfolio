# Open Terminal pilot (home MicroK8s only)

Phase 2 private `infra` review is staged internally but **not connected to WebUI**.
Its separate, zero-replica-by-default manifests and operator runbook are in
[infra-review/README.md](infra-review/README.md). Home MicroK8s now has both
private Pods manually scaled to one for isolation and snapshot verification.
Do not include that overlay in this portfolio pilot or attach its WebUI connection
until effective admin-only access and private-source handling are verified.
The GitHub App is installed on exactly `portfolio` and private `infra`; each
broker must request a token for **its own** repository only. Phase 2 broker
source and its locally imported digest are staged; the checked-in overlay
continues to default to zero replicas for rollback.
The infra terminal has no DNS/public HTTPS egress: only its in-namespace broker
on TCP 8001 via a Kubernetes-injected Service host. Its audited private snapshot
SHA is supplied out-of-git in an operator-owned ConfigMap, not public YAML.

Single-admin coding workspace, **not a multi-tenant sandbox**. This directory is intentionally absent from the root kustomization. Open WebUI is already reachable publicly at `chat.reyops.com` (new signups may be pending). A disconnected pod may be staged to test runtime isolation; **do not connect it to Open WebUI** until an operator has verified effective admin-only Open Terminal access controls in the running version. No terminal Ingress, Traefik path/host route, NodePort, or public endpoint is provided. Open WebUI (`default` namespace) must proxy the system-level integration to `http://open-terminal.code-agent.svc.cluster.local:8000`; do not add a browser/user-level direct connection.

The isolated runtime was tested on home MicroK8s before attaching it to Open WebUI: hardened image started, PVC bound, GitHub HTTPS resolved, private/cluster destinations timed out, non-WebUI pod ingress timed out, and missing/invalid keys returned 401 from the WebUI pod. Subsequently the admin-only system connection was installed: one approved non-admin test user received an empty terminal list and 403 from the proxy, then was removed; the connection has zero access grants, its key matches the Kubernetes Secret, and the public unauthenticated endpoint returns 401. The upstream `:v0.14.0` image tag did not exist, and the upstream `:0.14.0` image could not start with no-new-privileges until the local Dockerfile removed its file capability.

## Boundaries and limitations

- Dedicated `code-agent` namespace, one UID/GID 1000 pod, isolated PVC at `/home/user`, no hostPath, socket, BuildKit or runtime mounts, no service-account token. The API key is a separately created Kubernetes Secret, never a ConfigMap or checked-in YAML. Keep the Open WebUI connection key admin-only too.
- Inbound NetworkPolicy permits only pods labeled `app=openwebui` in `default` on TCP 8000. Outbound permits CoreDNS pods in `kube-system` on UDP/TCP 53 and public IPv4 HTTPS (TCP 443), excluding RFC1918, cluster private ranges, Tailscale CGNAT and link-local addresses. GitHub HTTPS can involve changing public addresses; **this policy does not restrict traffic to GitHub domains**, cannot prevent tunneling to other public HTTPS endpoints, and does not control DNS names. No egress to private git servers, databases, cluster services, or SSH/port 22. Verify Calico enforces policy and that DNS Service traffic is allowed after service translation. If the cluster uses a different DNS pod label, stop and revise the policy before release; never widen to all `kube-system` or all cluster IPs just to fix DNS.
- Upstream release `v0.14.0` is published to GHCR under image tag **`0.14.0` (without `v`)**. The local `Dockerfile` pins its verified multi-arch digest and removes the executable's `cap_setgid+ep` file capability and the passwordless sudo rule. The Deployment uses `allowPrivilegeEscalation: false`, drops all capabilities and uses `RuntimeDefault` seccomp. **Do not relax these settings to make it start.** These controls are not a complete multi-user sandbox; kernel/CNI/volume risks remain. Do not mount host sockets or add privileged mode as a workaround. PVC data may contain untrusted code; back it up or delete deliberately.
- TCP probes check listener availability, not auth, git or Open WebUI integration. Admission, namespace isolation, PodSecurity, CNI, DNS, PVC provisioner and image behavior must be tested on the **home** cluster. IPv6 egress is not granted by this IPv4 policy; verify dual-stack behavior separately if enabled.

## Staged rollout (manual authorization required)

1. From the **`portfolio/` repository root**, confirm `kubectl config current-context` is the intended **home MicroK8s** context, Calico policy enforcement is on, `kubectl get pods -n kube-system --show-labels` includes `k8s-app=kube-dns`, default StorageClass provisions an RWO volume writable by UID/GID 1000, and `kubectl get pods -n default -l app=openwebui --show-labels` matches the ingress selector. Confirm signup is pending and non-admin accounts **cannot** access Open Terminal integrations; inspect effective Admin → Integrations → Open Terminal access grants in the deployed Open WebUI version. If admin-only restriction cannot be verified, stop before creating a connection. Obtain explicit approval for rollout and for any future write-capable GitHub credentials.
2. From the parent `Personal/` directory build the hardened image **natively on caos**, where it is imported into MicroK8s: `./scripts/caos-build.sh portfolio/k8s/code-agent Dockerfile open-terminal-hardened:0.14.0-r1`. No registry or host socket is mounted in the coding pod. Render first from `portfolio/`: `kubectl kustomize k8s/code-agent` and, where safe and reachable, `kubectl apply --dry-run=server -k k8s/code-agent`. Server dry-run may reject namespaced objects if the namespace does not already exist. Do not apply the root kustomization. On approved rollout, create the namespace first: `kubectl apply -f k8s/code-agent/namespace.yaml`.
3. Generate a **new** random key out of git, in a private temporary file retained only until entered into Open WebUI. From the repo root (do not use shell tracing, print the key, or commit the file):

   ```sh
   umask 077
   KEY_FILE=$(mktemp)
   openssl rand -hex 32 | tr -d '\n' > "$KEY_FILE"
   kubectl -n code-agent create secret generic open-terminal-api-key \
     --from-file=OPEN_TERMINAL_API_KEY="$KEY_FILE"
   ```

   Securely transfer the contents of `$KEY_FILE` into the administrator-only connection when authorized; remove the temporary file after successful configuration (`rm -f "$KEY_FILE"`). Keep a secure operator-managed recovery copy if required. Never place it in a command argument, ConfigMap, screenshot, or repository. If a secret already exists, rotate deliberately (delete/recreate then restart pod and update WebUI connection); do not overwrite it blindly. Kubernetes Secrets are not automatically encrypted at rest: check cluster encryption and RBAC separately.
4. Apply **only** this overlay: `kubectl apply -k k8s/code-agent`. Check `kubectl -n code-agent rollout status deployment/open-terminal --timeout=300s`, `kubectl -n code-agent get pod,svc,pvc,networkpolicy`, `kubectl -n code-agent describe pod -l app=open-terminal` (do not paste secret-bearing output into tickets). Verify PVC is Bound, no restarts, and service is ClusterIP. Test DNS and `git ls-remote https://github.com/Caos-Ordenado/portfolio.git` and a read-only public HTTPS clone from inside the pod; confirm requests to private RFC1918/Tailscale targets and cluster-local services fail. Validate inbound is rejected from a non-WebUI pod, and accepted from the labeled WebUI pod (an unauthenticated HTTP 401/403 still demonstrates reachability). NetworkPolicy should block direct traffic from Traefik. Test policy with approved temporary diagnostic pods if tools are absent; remove them afterwards. Test API auth with an intentionally invalid key and confirm it is rejected without disclosing the real key in logs.
5. In the existing **public** Open WebUI, administrator only: Admin Settings → Integrations → Open Terminal → add **system-level** connection using the service URL above and the key from the temporary file. Leave disabled until access-grants are explicitly restricted to the approved admin account/group and verified in the actual version (UI naming may differ). Grant no default/all-users access, no user-level connection, no sharing the key with chat users, and no Traefik routing. Enable only for that admin; sign in as a non-admin approved account and a pending account to prove neither can use, enumerate, or invoke the terminal. If the current Open WebUI lacks enforceable per-connection restrictions, remove/disable the connection and stop the pilot.
6. Clone the **public** portfolio repository over HTTPS without tokens, deploy keys, credential helpers or direct push rights. The isolated PR broker holds the repo-scoped GitHub App credential; the model submits allowlisted source contents to it instead of using `git push`. The model may immediately publish a **public PR** containing those files without a human review first; checks and review gate merge and deployment. Do not submit secrets or private data, or paste bot credentials into terminal sessions, chats or the PVC. Test a benign command in the admin chat and verify ordinary chat behavior is unchanged.

The agent instructions are tracked at `k8s/code-agent/terminal-AGENTS.md` and
loaded by Open Terminal from its home directory at each turn. From the
`portfolio/` root, after reviewing changes to those instructions, sync them to
the persistent terminal workspace (no secrets in this file):

```sh
POD=$(kubectl -n code-agent get pod -l app=open-terminal -o jsonpath='{.items[0].metadata.name}')
kubectl cp k8s/code-agent/terminal-AGENTS.md "code-agent/$POD:/home/user/AGENTS.md"
kubectl -n code-agent exec deployment/open-terminal -- ls -l /home/user/AGENTS.md
```

## Rollback / recovery

Immediately disable and remove the system-level Open Terminal connection and revoke its grants in Open WebUI; verify non-admin and admin invocations no longer work. `kubectl -n code-agent scale deployment/open-terminal --replicas=0` stops execution while preserving the workspace. Delete the Secret to invalidate the key (`kubectl -n code-agent delete secret open-terminal-api-key`) and rotate any exposed credentials. If retiring the pilot, `kubectl delete -k k8s/code-agent` removes the namespace and **may delete the PVC and its data**; take a secure out-of-git backup first if data retention is required, inspect PV reclaim policy, and confirm deletion. Removing the manifests alone does **not** remove Open WebUI's persistent admin connection. If only a manifest update fails, restore the prior version of this overlay and reapply it after reviewing PVC/Secret effects; never roll back by opening an ingress.

## PR broker pilot (separate, cluster-internal only)

The PR broker is an additional `code-agent` Deployment and ClusterIP Service at `code-agent-pr-broker.code-agent.svc.cluster.local:8001`. It has **no** Ingress, Traefik route, NodePort or LoadBalancer; only `app=open-terminal` pods in the same namespace may connect on TCP 8001. The terminal's egress policy adds only that pod/port rule. The broker has no PVC, host mounts, service-account token or Kubernetes API access. Its GitHub App credential is a separately created Kubernetes Secret, not a ConfigMap; the terminal never receives the private key. Do not connect the broker to a public WebUI tool or expose its HTTP API. The model is authorized to submit allowlisted proposals, which immediately publish **public PRs**. Human review is required before merge and deployment, not publication.

The broker's egress copies the terminal's CoreDNS UDP/TCP 53 pod selector and public IPv4 TCP 443 allowlist with RFC1918, Tailscale CGNAT, loopback, link-local and other reserved ranges excluded. It is **not** GitHub-only and cannot enforce FQDNs. Check the actual cluster Service/Pod CIDRs and CNI policy behavior before rollout: policy evaluation after Service translation can differ, especially if cluster IPs are public. IPv6 is not explicitly permitted; validate dual-stack separately. Never widen to all cluster IPs or Tailscale to fix DNS. TCP probes only establish that the listener is open, not that GitHub permissions or API authorization work.

### Broker staged rollout and repeat verification (operator only)

The pinned and hash-locked image was built on `caos`; the internal broker is running 1/1. Server dry-run, terminal-to-broker `/health`, rejection of a non-allowlisted path (422), denied OpenWebUI-to-broker ingress and private/cluster egress, and the App installation's single-repository scope were verified. A **real broker-created PR and the self-hosted deploy runner have not yet been verified**. The steps below are for rebuilding, rotating credentials or repeating these checks; do not mistake TCP probes for proof of write authorization.

1. From `portfolio/`, review `services/code_agent_pr_broker/Dockerfile` and application against this contract before building: bind on 8001 as UID 10001; read `GITHUB_APP_ID`, `GITHUB_INSTALLATION_ID` and `GITHUB_APP_PEM_PATH=/run/secrets/github-app/private-key.pem`; work with a read-only root filesystem and no privileged mounts. Confirm installation repo scope/permissions. Valid model requests immediately publish public PRs; the human review requirement applies to **merge and deployment**, not PR creation. If the image or contract is missing or inconsistent, **stop**. Confirm home MicroK8s context, policy enforcement, kube-dns labels and cluster CIDRs as in the terminal rollout above. Check `kubectl kustomize k8s/code-agent` and `kubectl apply --dry-run=server -k k8s/code-agent` after confirming context and namespace exists.
2. From `Personal/`, build and import the local image using `./scripts/caos-build.sh portfolio/services/code_agent_pr_broker Dockerfile code-agent-pr-broker:pilot-4`. The directory and Dockerfile must exist before running this command. No registry push or host mount in the pod. Verify the imported digest `sha256:44a23d8e54d53d2d0284ee7ad6f8c0c15b3588ff8e846075098fa473cf569f0e` and create its `docker.io/library/code-agent-pr-broker@sha256:…` alias with `ctr images tag` on `caos` before applying the reviewed Deployment; `imagePullPolicy: Never` intentionally fails if the local digest is absent. After any code change rebuild and update this manifest to its new digest; never reuse a mutable `pilot-4` tag as the workload image.
3. On the **Mac**, obtain the GitHub App PEM through the approved private channel; keep it outside git. Set `PEM_FILE` to its absolute local path without printing, copying or inspecting the key. With shell tracing off, from `portfolio/` and the verified home context, create the namespace first if needed (`kubectl apply -f k8s/code-agent/namespace.yaml`), then create the Secret once:

   ```sh
   set +x
   kubectl -n code-agent create secret generic code-agent-github-app \
     --from-literal=APP_ID=5113000 \
     --from-literal=INSTALLATION_ID=165923991 \
     --from-file=private-key.pem="$PEM_FILE"
   ```

     IDs above identify the verified installation limited to `Caos-Ordenado/portfolio` and private `Caos-Ordenado/infra`, with Contents and Pull requests write and Metadata read. The App credential is shared, so each broker must request an installation token restricted to its own repository. Never put the PEM in a shell argument, logs, git, ConfigMap or terminal PVC. `kubectl -n code-agent get secret code-agent-github-app` checks existence without displaying data. If it already exists, stop and plan deliberate rotation; do not blindly replace. Protect Kubernetes Secret storage with cluster RBAC/encryption-at-rest controls.
4. After image and secret checks, apply only this overlay from `portfolio/`: `kubectl apply -k k8s/code-agent`. This also updates the terminal egress policy, so recheck terminal isolation. `kubectl -n code-agent rollout status deployment/code-agent-pr-broker --timeout=300s` and `kubectl -n code-agent get pods,svc,networkpolicy` must show a ready broker, ClusterIP-only service and both isolation policies. Do not wire an unreviewed bot endpoint into terminal automation.
5. From the terminal pod, test `/health` (no PR/write request): `kubectl -n code-agent exec deployment/open-terminal -- python3 -c 'import urllib.request; print(urllib.request.urlopen("http://code-agent-pr-broker.code-agent.svc.cluster.local:8001/health", timeout=5).status)'`. From a separate approved non-terminal diagnostic pod in `code-agent` and a pod in another namespace, confirm TCP 8001 is denied; delete diagnostic pods after testing. Test broker DNS/public HTTPS to GitHub and denied RFC1918/Tailscale/cluster-local egress using approved read-only probes; do not log tokens or PEM. Verify non-admin Open WebUI still cannot access the terminal before enabling any workflow.

### Broker rollback and checks

On failure, first `kubectl -n code-agent scale deployment/code-agent-pr-broker --replicas=0` and disable any broker caller. To return to the prior terminal-only state, restore the previous `networkpolicy.yaml` and `kustomization.yaml` from the reviewed revision, reapply the terminal egress policy, then `kubectl -n code-agent delete deployment/code-agent-pr-broker service/code-agent-pr-broker networkpolicy/code-agent-pr-broker-isolation`. Check the terminal still has DNS and public HTTPS access and that TCP 8001 is denied; do **not** use `kubectl delete -k k8s/code-agent` (it can delete the terminal PVC). Keep or delete the broker Secret only according to the operator's retention/rotation plan; if compromised, revoke/rotate the GitHub App key immediately and remove the Secret. For an image-only regression after a known-good release, roll back to the reviewed prior image tag and run rollout checks again; do not assume `rollout undo` can recover a locally deleted image.

Post-change: `kubectl -n code-agent rollout status deployment/code-agent-pr-broker`, `kubectl -n code-agent get endpoints code-agent-pr-broker`, `kubectl -n code-agent get networkpolicy code-agent-pr-broker-isolation open-terminal-isolation`, `kubectl -n code-agent get pods -l app=code-agent-pr-broker`, and `kubectl -n code-agent logs deployment/code-agent-pr-broker` (redact sensitive output). Confirm no restarts/resource pressure or unexpected Ingress/IngressRoute/NodePort/LoadBalancer, no Secret or private key in logs, denied non-terminal ingress, denied private/Tailscale/cluster egress, allowed DNS/public GitHub HTTPS, terminal reachability only on 8001, and unchanged terminal/WebUI access control. Stop the broker on any boundary failure.

## Post-change checks

`kubectl -n code-agent rollout status deployment/open-terminal`, `kubectl -n code-agent get endpoints open-terminal`, `kubectl -n code-agent get networkpolicy open-terminal-isolation -o yaml`, `kubectl -n code-agent logs deployment/open-terminal` (redact anything sensitive), and check pod restart count/resource pressure and PVC capacity. Confirm no `Ingress`, `IngressRoute`, `NodePort` or `LoadBalancer` was added for this service; test DNS, public GitHub HTTPS clone, denied private egress, denied unrelated pod ingress, failed unauthenticated API use, successful admin-only smoke command, and denied non-admin/pending WebUI access after every config or image change. If any check fails, disable/remove the WebUI integration and scale the deployment to zero before troubleshooting.
